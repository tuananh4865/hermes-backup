# Session 2026-06-17 — Loop Engineering Profile Creation (qa-agent + engineering-lead)

> **Context**: After system-wide Loop Engineering deployment on 2026-06-16, the user
> asked: "Theo tài liệu agent loop engineering thì còn chưa tạo profiles mới cho các
> agent có rule phù hợp nữa." Started iterating profile-by-profile, verifying each
> step with 3 layers (L1 code + L2 behavior + L3 future-proof).

## What was built

1. **`qa-agent` profile** — Independent quality verifier (separation of duties)
2. **`engineering-lead` profile** — Code implementation agent

## Key insights learned (codified in SKILL.md + here)

### Insight 1: Skill already had the answer — load BEFORE creating

**Real failure (2026-06-17)**: I created `qa-agent` and wrote a full 8KB SOUL.md from
scratch. Then discovered `agentic-company-setup/references/qa-agent-soul-template.md`
already has an **almost identical template**. Lesson: ALWAYS `skill_view` the umbrella
skill and its references BEFORE creating a new profile, not after.

**Test (would have caught it)**:
```bash
ls ~/.hermes/skills/autonomous-ai-agents/agentic-company-setup/references/
# Should see: qa-agent-soul-template.md
```

**Fix for future**: At the start of any "create a new agent profile" task, run:
```bash
skill_view agentic-company-setup
# THEN read the references/ directory
# THEN decide: use template OR write custom
```

### Insight 2: .env pitfall — already documented, hit it anyway

I hit the exact pitfall the skill already documents: copying just `MINIMAX_API_KEY=...`
gave 401 errors. Fix: copy the FULL `.env` from a working profile (e.g. `coder`).
This is the third time the user has emphasized this lesson; the skill doc is correct.

**What worked**: `cp ~/.hermes/profiles/coder/.env ~/.hermes/profiles/qa-agent/.env` + chmod 600.

### Insight 3: Model selection — NEW pitfall NOT in skill

**qa-agent** started with `MiniMax-M3` (copied from default config). Hit 401 because
the local API key didn't have M3 access. Then I tried `MiniMax-M2.7` and it worked.
But for `engineering-lead` doing complex multi-tool code tasks, M3 hit 120s timeout
on a handoff-format test, while M2.7 finished in ~10s.

**This is a NEW pitfall that wasn't in `agentic-company-setup` before.** I added it
to the SKILL.md under "MODEL SELECTION" section.

**Practical rule**:
- Quick verify/web-search tasks → M3 if available
- Multi-tool code generation → M2.7 (avoid 120s timeouts)
- Always run the PONG test first to confirm model + API key works

### Insight 4: 3-Layer verify pattern works end-to-end

For each profile, the user wanted **3 layers of verification**:
- **L1**: Code/config exists (file presence, correct size, right format)
- **L2**: Behavior works (real test query, real output)
- **L3**: Future-proof + integration (CLI wrapper, state file, pair with another agent)

For `qa-agent + engineering-lead`, the L3 test was a maker-checker pair test:
1. engineering-lead writes `/tmp/el-test/calc.py` (3 type-hinted functions)
2. engineering-lead runs it locally → output 5 (correct)
3. qa-agent independently runs the file → all 3 functions verified
4. qa-agent verdict: PASS 10.0/10

This is the **dynamic maker-checker loop** the user described in the conversation:
> "Bắt đầu từng cái, làm xong tới đâu check verify lại tới đó đảm bảo mọi thứ hoạt
> động từng bước nếu lỗi thì research và làm lại cho đến khi hoàn thành, đó là loop
> mà anh muốn."

### Insight 5: User's "self-verification bias" rule

> "Nếu em tự check nó sẽ không còn khách quan nữa và có tỉ lệ cao bị tự nhận PASSED."

This is a **foundational rule** for multi-agent systems. The skill already had it
under "Separation of Duties" section. After this session it's stronger because we
**proved the rule works** with a real pair test.

## What works well — keep doing

- Copy `.env` from `coder` (full file, not just API key)
- Use `~/.local/bin/<agent>` wrapper (auto-generated by `hermes profile create`)
- Run PONG test before customization
- Follow SOUL.md template from `references/qa-agent-soul-template.md`
- Use 6-check rubric (Completeness, Correctness, Sources, Logic, Style, Evidence)
- Verdict format: `VERDICT: PASS/WARN/FAIL` + `SCORE: 0-10` + `EVIDENCE:`

## What was slow / annoying — improve next time

- Creating `qa-agent` SOUL.md from scratch when template already existed — wasted ~5 min
- The "M3 vs M2.7" question required 2 round trips to resolve — should have been
  in the skill as a pre-flight check
- User had to correct me on Fable-5 ("còn thiếu fable 5") — should have run
  `bash ~/.hermes/scripts/check-fable5-compliance.sh` BEFORE claiming done
