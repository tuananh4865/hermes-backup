## MiniMax Configuration Error (2026-05-18 Late)

### Symptom
Gateway repeatedly fails to start with:
```
SecretProviderResolutionError: Secret provider "minimax" is not configured (ref: env:minimax:MINIMAX_API_KEY)
Gateway failed to start: Startup failed: required secrets are unavailable.
```

### Root Cause
The `models.providers.minimax` config uses `apiKey: "ref+env:minimax:MINIMAX_API_KEY"` — this asks the gateway to resolve via a secret provider named "minimax". The gateway has no secret provider with that name, even though:
1. The @openclaw/minimax plugin auto-enables (detected automatically)
2. The MINIMAX_API_KEY environment variable IS set in the shell
3. The provider catalog shows "M2.7 (recommended)"

The issue is that `env:minimax:MINIMAX_API_KEY` means "use secret provider 'minimax' to look up env var MINIMAX_API_KEY", NOT "look up env var MINIMAX_API_KEY directly". The naming convention `provider:env_var` requires a matching secret provider configuration.

### Possible Fixes (not yet tested)
1. Change apiKey reference from `ref+env:minimax:MINIMAX_API_KEY` to just an inline string (but that exposes the key in config)
2. Add a secrets provider configuration in openclaw.json under a `secrets.providers.minimax` block
3. Use `ref+env:default:MINIMAX_API_KEY` if a "default" secret provider exists
4. Set up a secrets provider that can resolve minimax API keys

### Config That Triggered This

{
  "models": {
    "providers": {

        "provider": "@openclaw/minimax",
